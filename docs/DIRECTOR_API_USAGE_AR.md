# مراقبة استهلاك المخرج السحابي — 17 أكتوبر 2026

## ما نُفذ
- ربط عداد الاستخدام بواجهة المخرج الحالية **دون إضافة زر جديد**. لا يستدعي الخادم عند كل كلمة؛ يستعلم بعد تفعيل السحابة وبعد نتيجة طلب التحليل.
- يستلزم طلب `GET /api/director/status` رمز المحاضر؛ يعيد توفر المفتاح وعدد الطلبات المستخدمة والمتبقية وحد `DIRECTOR_MAX_CALLS` وعدد التحليلات الناجحة والفاشلة ومجموع توكنات الإدخال والإخراج **المعلنة فعلياً من الخدمة**.
- الطلبات التي يرد عليها المزود بدون بيانات استخدام تُحصى مستقلة وتُذكر بصراحة؛ تُسجَّل البيانات الرقمية المُعلنة حتى لو فشل تحقق المشهد لاحقاً.
- أي اتصال محاول يُحتسب ضمن سقف الطلبات (حتى عند خطأ الشبكة)، ضماناً ألا تعيد المحاولة تلقائياً استهلاكاً غير مضبوط؛ انتظار 12 ثانية بين الطلبات ما زال سارياً.
- الاستعلام عن العداد لا يرسل محتوى المحاضرة ولا يستدعي OpenAI؛ التفعيل السحابي يبقى اختيارياً، والشرائح المحلية والفيديو يعملان مستقلاً عنه.

## حدود مهمة
- **لا يحسب أسعاراً بالدولار**، لأن السعر قد يختلف حسب النموذج أو تفاصيل الخدمة، ولا يجوز اختراع قيمة سعرية. قيمة `costUsd` متعمدة = null.
- **العداد محفوظ في ذاكرة عملية الخادم** ويبدأ من الصفر عند إعادة تشغيله؛ ليس كشف فواتير دائماً ولا سقف إنفاق مالي مضمونا. سقف عدد الطلبات `DIRECTOR_MAX_CALLS` لا يقيد سعر كل طلب؛ `max_output_tokens:350` حد توليد فقط.
- الحماية الحالية تتعلق بمخرجات API؛ لا تثبت أداء STT المحلي أو الاستجابة على Mac أو تشغيل الصوت دون اتصال.

## الاختبار
`npm run test:usage` يستخدم خدمة مزيفة داخل Node، دون مفتاح API حقيقي أو تكاليف، ويفحص عدد الطلبات والمهلة وسجلات التوكنات ومحدودية الأرقام. `npm run test:e2e` يتحقق من حماية endpoint ومن عرض حالة السحابة في Chromium. لم يُختبر السعر الفعلي المدفوع.
