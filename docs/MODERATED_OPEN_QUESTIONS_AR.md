# أسئلة الطلبة المكتوبة عبر QR مع مراجعة المحاضر — 17 أكتوبر 2026

## الاستخدام والتنفيذ
داخل رابط QR نفسه الذي يستخدمه الطلاب للتصويت توجد نافذة صغيرة قابلة للفتح بعنوان «عندك سؤال للمحاضر؟» تعمل حتى بدون سؤال تصويت مفتوح. يكتب الطالب سؤاله ويرسله، ثم يشاهد إقراراً باستلامه **للمحاضر فقط**.

توجد قائمة «أسئلة الطلبة المفتوحة» داخل لوحة التصويت المدمجة في واجهة المحاضر. لا يجري إسقاط السؤال على شاشة العرض ولا إعادة نشره للطلبة آلياً. يعرض السؤال كنص آمن غير قابل لتنفيذ HTML؛ ويمكن للمحاضر إزالته. القائمة محمية بـ`X-Admin-Token` ولا تصل عبر حالة الطالب العامة.

## حماية البيانات والحدود
- 280 حرفاً كحد أقصى للسؤال، و100 سؤال معلّق لكل جلسة. يقيّد الخادم إرسال الجهاز الواحد إلى مرة كل 30 ثانية داخل عملية الخادم.
- يُستخدم رمز الهاتف للتحقق من معدل الإرسال فقط داخل ذاكرة الخادم، **ولا يُخزن** الرمز أو اسم أو IP الطالب داخل سجل الأسئلة. نص السؤال نفسه محفوظ على قرص Mac ضمن ملف جلسات التصويت ليستمر بعد إعادة التشغيل؛ لا تكتبوا أسماءً أو بيانات شخصية في السؤال. عند إزالة السؤال يُحذف من قائمة الجلسة المخزنة.
- يستطيع الطالب إعادة توليد الرمز أو استغلال أجهزة مختلفة؛ المنع ليس هوية مؤسسية أو حماية كاملة من الإغراق. عند إعادة تشغيل الخادم تبدأ ذاكرة تحديد المعدل من جديد.
- لا يوجد تصنيف دلالي، ولا استنتاج سوء فهم الطالب، ولا عرض تلقائي للأسئلة، ولا دفع بيانات لخدمة سحابية. يجب أن يقرر المحاضر بنفسه كيف يستعمل السؤال في الدرس.
- الخدمة تعمل على LAN إن سمحت شبكة الجامعة باتصال الأجهزة بخادم المحاضر. لم يتم التحقق على هواتف أو Mac فعلي.

## الاختبار
`npm run test:vote-rounds` يفحص القبول/الرفض/الخصوصية، و`npm run test:vote` يشغّل Chromium لخمس جلسات أجهزة افتراضية ويتحقق من الاستلام والمراجعة وصلاحيات API ومقاومة تنفيذ HTML واستمرار البيانات بعد إعادة التشغيل. بقية اختبارات العرض والفيديو تبقى ضمن CI.
