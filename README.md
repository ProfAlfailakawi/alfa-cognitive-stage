# ALFA Cognitive Stage

منصة عرض للمحاضرات بوضعين: **نافذة المحاضر** (ملاحظات وتحكم) و**نافذة الطلبة** (الشريحة فقط بلا أدوات).

## ما يعمل الآن (مُختبَر)

- **تحويل ملف PowerPoint إلى حزمة محاضرة** (`tools/build_bundle.py`):
  - يعرض الشرائح كما هي بمحرك LibreOffice، فيحافظ على التصميم والخطوط.
  - يستخرج الفيديوهات المضمّنة ويحفظ موضعها ومقاسها من الشريحة.
  - يحوّل الفيديو إلى MP4 (H.264) ونسخة WebM احتياطية، ويحفظ ملاحظات المحاضر.
  - لا يعدّل ملف PowerPoint الأصلي، ولا يُرفع إلى Git.
  - يسجّل الروابط الخارجية المكسورة في `problems` داخل الـmanifest.
- **العرض في المتصفح** (`web/`): تنقّل بالأسهم والمسافة، ونافذة ثانية للطلبة تتزامن معها عبر `BroadcastChannel`.
- **الفيديو**: تشغيل وإيقاف ومزامنة مع نافذة الطلبة، وتحديد موضعه وفق الشريحة.
- **العودة الفورية**: زر أو مفتاح `E` يوقف الفيديو ويعيد الشريحة الأساسية.
- **التصويت الطلابي** (`server/votes.mjs`، `web/vote.html`، `web/vote-admin.html`):
  - المحاضر يفتح «التصويت» من شاشته، ينشئ جلسة برمز QR، ويضيف أسئلة من 2 إلى 6 خيارات.
  - الطالب يمسح QR ويجيب دون حساب. كل جهاز يحصل على رمز عشوائي محلي، ويُمنع التصويت المكرر إلا إن سُمح بالتغيير.
  - سؤال واحد مفتوح في كل مرة. الطالب الذي ينتظر يرى السؤال التالي تلقائياً دون إعادة فتح الرابط.
  - النتائج تُحفظ في `data/votes.json` وتبقى بعد إعادة تشغيل الخادم.
  - الحد: صوت واحد لكل جهاز كل 500 ms، و1000 مشارك كحد أقصى لكل سؤال، وطلب بحجم 4 KB كحد أقصى.
- **اختبارات**:
  - `npm run test:build`: اختبارات بناء الحزمة (بدون محرك العرض).
  - `npm run test:e2e`: فحوص المتصفح للعرض (التنقّل والتزامن والفيديو والعودة).
  - `npm run test:vote`: فحوص التصويت بخمسة أجهزة متصفح منفصلة، والتكرار، والتغيير، والنتائج بعد إعادة التشغيل.

## ما لم يُنفَّذ بعد

- **الحركات (Animations) داخل الشرائح**: لا تُنقل. الشرائح تُعرض في حالتها النهائية.
- **المخطط البياني الأصلي**: الإحصائيات في المحاضرة صور، لذلك لا توجد حركات مخططات تُنقل.
- **المخرج الذكي الخفي**: لا يوجد تعرّف على الكلام ولا أي استدعاء لـAPI، بانتظار مفتاح API واختبار صوت حقيقي.
- **استضافة التصويت على الإنترنت**: التصويت يعمل حالياً على الخادم المحلي فقط. الطلبة يحتاجون الوصول إلى الخادم عبر الشبكة، وهذا يتطلب استضافة خارجية لم تُختر بعد، وسأبحث عن خدمة مجانية وأختبرها قبل اعتمادها.
- **التصويت على الهواتف الحقيقية**: الاختبارات تستخدم متصفحات منفصلة بأجهزة افتراضية، لا هواتف حقيقية.
- **الرسوم البصرية المولّدة** (الإنفوجرافيك الخفيف من الذكاء الاصطناعي): لم تُنفّذ بعد.
- **اختبار على Mac وPowerPoint**: لم يُجرَ. الاختبارات هنا على Chromium وLibreOffice فقط.

## التشغيل

المتطلبات: Node.js 22، Python 3 مع `python-pptx` و`lxml` و`Pillow`، وLibreOffice وpoppler (`pdftoppm`) وffmpeg.

```bash
python3 tools/build_bundle.py /path/to/lecture.pptx   # يكتب bundles/<id>/ ويحدّث current.json
npm start                                             # ثم افتح http://localhost:4173
```

- المحاضر: `http://localhost:4173/#presenter`
- الطلبة: يُفتح من زر «فتح نافذة الطلبة» أو `http://localhost:4173/#audience`

اختبارات المتصفح تحتاج Playwright. على هذا الجهاز تُربط بالحزمة العامة:

```bash
mkdir -p node_modules && ln -s /opt/node22/lib/node_modules/playwright node_modules/playwright
npm run test:e2e
```

## الاختصارات

| المفتاح | الوظيفة |
|---|---|
| ← / PageUp | الشريحة السابقة |
| → / PageDown / مسافة | الشريحة التالية |
| Home | أول شريحة |
| E أو Esc | عودة فورية إلى الشريحة الأساسية |
| V | تشغيل/إيقاف فيديو الشريحة |

## أمان التصويت

- رمز المحاضر يُطلب عند تشغيل الخادم، ويُحفظ في الطرفية، ولا يظهر للطلبة. إن لم يُعيَّن `ADMIN_TOKEN` يُولَّد عشوائياً عند كل تشغيل.
- الطالب يرى سؤاله المفتوح وإجابته فقط، ولا يرى نتائج إلا بعد أن يُظهرها المحاضر.
- لا تُخزَّن أسماء ولا بيانات شخصية. الرمز المحلي للجهاز عشوائي ولا يربط الإجابة بشخص.
- يُقبل النص كنص فقط، ويُعرض بطريقة تمنع تنفيذ أي كود داخل الصفحة.
